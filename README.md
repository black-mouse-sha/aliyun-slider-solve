# 反检测代理栈 · 三层身份

仓名：`antidetect-proxy-stack`
副标题：**Identity layering for multi-account work.**
中文说明：一台电脑跑多个账号时，把「网络身份／设备身份／行为身份」拆开管的三支技能。
署：**black-mouse-sha**

> 文档状态：**v0.1**，记录一次真实折腾的全过程，不是教程书。
> 已在本机实际跑通的部分：代理经机场中转后独立端口出口正确、指纹浏览器窗口与普通浏览器出口分离、阿里云滑块通过一次。
> 已实测失败的部分：同一站点的中文域名滑块连续 3 次未过。**这些失败也写进了技能正文，不做粉饰。**
> 未验证的部分：静态 ISP 的接入、更换分辨率后二次模型系数是否需重标、某个具体平台的风控命中率变化。
> **本文只保证「步骤可照做、症状可对照」，不承诺任何平台的安全性提升。**

## 这是什么

一个人在一台电脑上，让网站相信「这些是不同的人」。

难的不是装工具，是三件容易混在一起的事：

- **网络身份**（IP、时区、语言、坐标）—— 归代理管
- **设备身份**（UA、Canvas、WebGL、字体、分辨率）—— 归指纹浏览器管
- **行为身份**（点击节奏、输入速度、活跃时段）—— 归你自己，工具帮不上

三支技能分别处理这条链上最容易翻车的三段：

| 技能 | 解决什么 | 一句话 |
|---|---|---|
| [`proxy-fingerprint-layering`](skills/proxy-fingerprint-layering/) | 配完代理还是被识别 | IP 归代理，长相归指纹，两样都要对 |
| [`clash-chain-proxy`](skills/clash-chain-proxy/) | 代理连不上／主流量偷跑 | 非直连才加跳板，加了就关进独立端口 |
| [`aliyun-slider-solve`](skills/aliyun-slider-solve/) | 滑块一直不通过 | F015 改算法，F001 改环境 |

三支可以单独装，按顺序装效果最好：先分层 → 再接通 → 最后处理拦截。

## 对我有什么用

- **少花冤枉钱。** 按流量计费的住宅代理，如果主流量偷偷走了它，一小时能烧掉几顿饭钱。第二支技能里的 `append` 与 `DIRECT 排第一` 两条，就是为这个写的。
- **失败能定位。** 滑块失败有判定码，代理失败有错误码，指纹失败有两个环境对比。每个症状都能倒推到一个具体原因，不用靠猜。
- **知道边界在哪。** 每支技能都有「验证到哪」一节，写清哪些是实测的、哪些只是机制说明。不做效果承诺。
- **换工具不用重学。** 方法在三层上是稳定的；指纹浏览器换一家、代理换一家，分层逻辑不变。

## 一次完整链路

```
买代理（住宅 / ISP）
      ↓
判断能不能直连 ──能──→ 指纹浏览器里直接填账密
      ↓ 不能（403 forbidden ip=）
Clash 里加 dialer-proxy 经机场中转
      ↓
开独立端口（如 7920），主流量不受影响
      ↓
指纹浏览器窗口 / 命令行 指向这个端口
      ↓
核对四项：时区、语言、坐标、WebRTC
      ↓
两个环境各测一次 ipinfo.io，结果必须不同
      ↓
遇到滑块 → 先看判定码再动手
```

## 三层各由谁负责

同一件事，哪部分归工具、哪部分归你：

| 环节 | 代理负责 | 指纹浏览器负责 | 必须你自己做 |
|---|---|---|---|
| 你从哪来 | IP、国家、城市、运营商 | — | 选哪种代理（动态 / 静态） |
| 你用什么电脑 | — | UA、Canvas、WebGL、字体、硬件 | 核对时区语言坐标 WebRTC |
| 你像不像真人 | — | — | 操作节奏、内容风格、作息 |
| 账号归属 | 一窗口一 IP | 一窗口一指纹 | 一窗口一账号，永远不换 |

**任何一层单独做到极致都没用。** 这是本文最想说的话。
