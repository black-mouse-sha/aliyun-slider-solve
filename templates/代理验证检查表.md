# 代理验证检查表

配完一个指纹浏览器窗口之后，逐项打勾。**任何一项没勾，就先别登业务账号。**

复用时说明：这份表核对的是「当前版本、当前环境」。换了代理、换了窗口配置、换了电脑之后，受影响的行要重核。

---

## 一、代理层（填完代理立即核）

| # | 检查项 | 怎么核 | 通过标准 | ✓ |
|---|---|---|---|---|
| 1 | 代理能连上 | 窗口里点「代理检测」 | 绿字，显示目标地区 | ☐ |
| 2 | 出口 IP 是代理 IP | 窗口内访问 `ipinfo.io` | 显示代理 IP，不是本地 IP | ☐ |
| 3 | 运营商是 ISP | 看 `ipinfo.io` 的 `org` 字段 | 出现 Comcast / Charter / Verizon / Spectrum 这类住宅 ISP，**不是** DigitalOcean / Vultr / Cloudflare | ☐ |
| 4 | 不是机房段 | 看同一页的 `proxy` 或第三方风险分 | 不要出现「代理服务器：是」 | ☐ |

> 第 3 项最容易漏。机房 IP 也是「美国的 IP」，但平台一眼就看出来。

---

## 二、指纹层（只有四项要管）

| # | 检查项 | 怎么核 | 通过标准 | ✓ |
|---|---|---|---|---|
| 5 | 时区跟着 IP 走 | 窗口配置里看「时区」 | 与代理所在时区一致（纽约 = `America/New_York`） | ☐ |
| 6 | 语言 | 窗口配置里看「语言」 | `en-US,en`，或与 IP 国家一致 | ☐ |
| 7 | 坐标 | 窗口配置里看「地理位置」 | 与代理城市一致（纽约约 `40.714, -74.006`） | ☐ |
| 8 | WebRTC | 窗口配置里看「WebRTC」 | 「替换」或「禁用」 | ☐ |

> 其余项（Canvas、WebGL、字体、分辨率、硬件、UA）保持默认随机即可。**手改反而容易造出自相矛盾的指纹。**

---

## 三、泄漏检查（用检测站看结果）

访问 `https://browserleaks.com/ip` 与 `https://browserleaks.com/webrtc`

| # | 检查项 | 通过标准 | ✓ |
|---|---|---|---|
| 9 | IP | 代理 IP | ☐ |
| 10 | 时区 | 与 IP 一致 | ☐ |
| 11 | WebRTC | `No leak`，或显示代理 IP，**不能出现本地 IP** | ☐ |
| 12 | DNS | 不出现本地运营商 DNS | ☐ |
| 13 | Canvas | 有哈希值即可，值本身不用管 | ☐ |

---

## 四、隔离对比（最容易漏的一步）

同时开两个环境，各访问一次 `ipinfo.io`：

| 环境 | 期望出口 | ✓ |
|---|---|---|
| 指纹浏览器窗口（填了代理） | 代理 IP / 代理城市 | ☐ |
| 普通浏览器（走系统代理或直连） | 本地或机场 IP，**与上面不同** | ☐ |

**两个结果一样 = 代理没生效，或窗口填成了系统代理端口。**

---

## 五、长期纪律（每做一个账号就核一次）

| # | 检查项 | ✓ |
|---|---|---|
| 14 | 一个窗口只登一个业务账号，永不复用 | ☐ |
| 15 | 窗口里没有登录任何私人账号（微信／支付宝／常用邮箱） | ☐ |
| 16 | 这个窗口的代理是独占的，没有和别的窗口共用同一个 IP | ☐ |
| 17 | 记下了这个窗口对应的账号，下次还用同一个窗口 | ☐ |

---

## 出问题时先看这里

| 症状 | 大概率是 | 回到哪一项 |
|---|---|---|
| 检测站显示本地 IP | 在普通浏览器测的，或窗口没填代理 | 第 2、13 项 |
| IP 对了但时区是本地 | 只填了代理 | 第 5 项 |
| 显示「代理服务器：是」 | 机房 IP | 第 3 项 |
| 真实 IP 泄漏 | WebRTC 没关 | 第 8、11 项 |
| 多个账号被关联 | 多窗口共用 IP | 第 16 项 |
| 窗口打不开网页 | 代理端口不存在（Clash 关了或配置被撤） | 见 `../skills/clash-chain-proxy/` 第 5 节 |
