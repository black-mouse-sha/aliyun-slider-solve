# 代理与指纹是两件独立的事

属于开源包 反检测代理栈（antidetect-proxy-stack）。

## 含什么

一张三层分工表、四个必须手动核对的项、一套「两个浏览器对比」的验证方法、五种最常见的死法。核心是一条：**代理决定你从哪来，指纹决定你是谁，两者由不同组件负责，谁也不能替谁干活。**

## 适合谁

- 刚买完指纹浏览器和住宅代理、以为「填上代理就完事」的人
- 在检测站看到本国 IP，怀疑代理没生效的人
- 想让网站认为自己是某个海外真实用户的人（跨境电商、社媒、广告投放）
- 被「指纹浏览器能不能改 IP」「时区要不要跟代理一致」这类问题困住的人

## 怎么用

1. 先看第 1 节三层分工，把「谁负责什么」钉死，别指望一个组件干两件事。
2. 填完代理后，按第 2 节四项逐个核对——这四项是唯一必须手动干预的。
3. 按第 3 节方法验证：在两个不同的浏览器环境里各访问一次检测站，出口必须不同。
4. 出问题时对照第 4 节五种死法，按症状找原因。

## 依赖

- 一个指纹浏览器（本文以比特浏览器 BitBrowser 为例，其他同类产品字段名不同、逻辑一致）
- 一条可用的代理（住宅／ISP 均可；能否直连见 `../clash-chain-proxy/`）
- 一个检测站：`ipinfo.io`（看 IP 归属）与 `browserleaks.com`（看指纹与泄漏）

## 示例

完整的一次配置与两次对比验证，见包根 `examples/bitbrowser-download/README.md`。

## 验证到哪

三层分工与四项核对是**机制说明**，不是效果承诺。已在本机实测：同一台电脑下，普通浏览器走系统代理得到 `Cloudflare / 洛杉矶`，指纹浏览器窗口走独立端口得到 `Charter Communications / 纽约`，两者出口与服务商均不同——分层本身生效。

**未验证**：本方法能否降低某个具体平台的风控命中率。任何声称「配好就封不了号」的说法都超出本文范围。是否真的安全，取决于代理质量、行为习惯、收款方式、内容相似度等本文不覆盖的因素。

一句话：**IP 归代理，长相归指纹，两样都要对，少一样就是白配。**

## 0. 先钉死一件事

**指纹浏览器一个字节的 IP 都不改。**

它只做一件事：让浏览器「看起来像另一台电脑」。你的网络出口，永远是代理决定的。

所以「装了指纹浏览器就安全了」这句话，等于「换了衣服就不用买票了」。

## 1. 三层分工

| 层 | 由谁负责 | 决定什么 | 网站怎么看 |
|---|---|---|---|
| **网络身份** | 代理服务器 | IP、国家、城市、运营商、时区 | 你从哪来 |
| **设备身份** | 指纹浏览器 | UA、Canvas、WebGL、字体、分辨率、硬件 | 你用什么电脑 |
| **行为身份** | 你自己 | 点击节奏、输入速度、活跃时段、内容风格 | 你像不像真人 |

三层里只有前两层能靠工具解决。第三层工具帮不了，这也是为什么「指纹完美」的账号照样会被封。

### 一个常见误解

> 「指纹浏览器会把 IP 定位改得更稳定」

**错。** 指纹浏览器不碰 IP。「稳定」来自代理类型：静态 ISP 一个 IP 长期不变，动态住宅每 N 分钟换一次。跟指纹浏览器无关。

## 2. 只有四项必须手动核对

指纹分两类，待遇完全不同：

| 类型 | 举例 | 要不要管 |
|---|---|---|
| **设备固有特征** | CPU 核数、内存、显卡、Canvas、WebGL、AudioContext、字体列表、分辨率 | **不用管**，随机即可。纽约人也用联想、也用 8 核 |
| **地理关联特征** | 时区、语言、经纬度坐标、WebRTC | **必须管**，要跟代理所在地一致 |

四项的具体填法（以纽约代理为例）：

| 项目 | 填什么 | 不填会怎样 |
|---|---|---|
| 时区 | `America/New_York`，或选「跟随 IP 自动匹配」 | 美国 IP + 北京时间，一眼假 |
| 语言 | `en-US,en` | 美国 IP + 中文 `Accept-Language`，矛盾 |
| 地理位置 | 允许，经纬度填代理所在地（纽约约 `40.714,-74.006`） | 坐标对不上 IP，高级检测能看出 |
| WebRTC | **替换** 或 **禁用**，绝不选「透传／真实」 | 网站能绕过代理读到你真实 IP，前面全白费 |

**WebRTC 单独强调**：这是唯一一项能「让代理彻底失效」的开关。不关它，网站依然拿得到你的真实内网／公网 IP。

## 3. 验证方法：两个环境对比

只在一个地方测，永远测不出问题。要同时看两个：

```
环境 A：填了代理的指纹浏览器窗口
环境 B：走系统代理（或直连）的普通浏览器
```

各自访问 `ipinfo.io`，**两个结果必须不同**。

**期望结果对照：**

| 项目 | 环境 A（代理窗口） | 环境 B（普通浏览器） |
|---|---|---|
| IP | 代理 IP | 本地或机场 IP |
| 城市 | 代理所在城市 | 本地或机场所在城市 |
| 运营商 | 代理的 ISP（如 Charter、Comcast、Verizon） | 本地运营商或云厂商 |
| 时区 | 跟代理一致 | 跟本地一致 |

再看 `browserleaks.com`：

| 检查项 | 期望 |
|---|---|
| WebRTC | `No leak`，或显示代理 IP |
| Canvas | 一串哈希，不用管具体值 |
| 时区 | 与 IP 所在时区一致 |
| 语言 | `en-US`，与界面语言一致 |

### 一个真实的判读错误

有人打开 `检测站/ip/1.2.3.4` 这种**带 IP 参数**的链接，看到结果是中国，就以为代理没生效。

**带 IP 的页面是「查这个 IP 属于谁」，不是「查我现在是谁」。** 查自己要用不带参数的空页面：`ipinfo.io`、`ip.sb`。

## 4. 五种常见死法

| 症状 | 真正原因 | 改法 |
|---|---|---|
| 检测站显示本国 IP | 在普通浏览器测的，或窗口没填代理 | 在指纹浏览器**窗口内**测 |
| IP 对了但时区是本地 | 只填了代理，没核对时区 | 第 2 节四项逐个核 |
| 显示「代理服务器：是」 | 用了机房 IP，或代理被标记 | 换住宅／ISP 类代理 |
| 泄露真实 IP | WebRTC 没关 | 改成「替换」或「禁用」 |
| 多个窗口互相关联 | 多个窗口共用一个 IP | 一窗口一 IP，见 `../clash-chain-proxy/` |

## 5. 一条长期习惯

**一个窗口 = 一个账号 = 一个 IP，永远不换。**

今天窗口 A 登账号甲，明天、下个月还是窗口 A 登账号甲。别删了重建，别混着登。

同理，**永远不要在窗口里登自己的私人账号**（微信、支付宝、常用邮箱）。一次登陆，前面所有隔离就串味了。

（末尾补一句：本文只讲「怎么让两个身份各自成立」，不评价你要拿它做什么。）
